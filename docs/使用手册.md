# MDLineage 使用手册

本手册是 MDLineage 的完整使用文档，覆盖安装、配置、CLI 命令、诊断码、编辑器与 AI 集成、CI 门禁和常见陷阱。文中的命令与输出均为在仓库 HEAD（commit `15f216f`，全部包版本 `0.1.0`）上的真实运行结果（2026-09-24）。

相关页面：[architecture.md](architecture.md)（架构设计）、[frontmatter-spec.md](frontmatter-spec.md)（元数据规范草案）、[line-ending-management.md](line-ending-management.md)（行尾治理）、[dir-conventions.md](dir-conventions.md)（目录规范，开放设计）、[progress.md](progress.md)（进度台账）。

## 1. MDLineage 是什么

MDLineage 是一套面向 Markdown 仓库的变更感知上下文索引与校验工具集，让编码代理（coding agent）能发现文档之间的关系、评估一次文档变更的影响范围，并保证文档自身从 Front Matter 语法到目录布局都保持健康。

它建立在两个观点之上：

- Front Matter 是**可评审的事实来源**：稳定的文档身份（`id`）和已确认的关系（`relations`）只写在文档头部，人看得见、评审得了。
- RAG 与图分析只是**维护工具**：用于发现候选关系、主题、重复与矛盾，日常检索仍以文件路径、Markdown 链接和 grep 等仓库原生手段为主。

### 1.1 五大包

| 包 | 角色 |
| --- | --- |
| `@mdlineage/validator` | 传输无关的校验核心：解析、JSON Schema、工作区索引、baseline。 |
| `@mdlineage/remark-lint-mdlineage` | remark 插件，校验未保存的编辑器缓冲区而非磁盘副本。 |
| `@mdlineage/cli` | 提供 `mdlineage` 二进制：批量校验、CI 门禁、`init`、`fix`。 |
| `@mdlineage/language-server` | 基于 stdio 的专用语言服务器（LSP）。 |
| `@mdlineage/mcp-server` | 基于 stdio 的 MCP 服务器：面向 LLM 代理的校验、Schema 与元数据工具。 |

### 1.2 四大支柱与交付状态

| 支柱 | 内容 | 状态 |
| --- | --- | --- |
| P1 关系索引 | 跨文档关系由语义分析提议、确认进 Front Matter，变更时做影响分析 | 校验与索引层已交付；语义检索与关系推断未开始 |
| P2 语法与元数据校验 | 一个校验核心同时服务 LSP、CLI、CI、MCP，诊断码稳定 | 已交付 |
| P3 行尾卫生 | 检测、修复并预防跨平台编辑造成的换行符漂移 | 已交付 |
| P4 目录规范约束 | 目录意图契约（`layout.intent`）、例外生命周期、目录拓扑与链接重构引擎 | 已交付（`move`/`organize` 命令、MDL501–MDL505） |

## 2. 环境要求与安装

要求 Node.js `>= 20`（根 `package.json` 的 `engines`；CI 在 Node 20 与 22 上验证，本地 Node 24 同样通过全部测试）和 npm workspaces（本仓库为 `type: module`）。

```bash
git clone https://github.com/x-dc-coder/md-lineage.git
cd md-lineage
npm ci
npm run build
```

`npm run build` 执行 `tsc -b && node scripts/ensure-bin-exec.mjs`。后半段不可省略：npm 在 `dist/` 尚不存在时不会创建 bin 软链接，`ensure-bin-exec.mjs` 会在构建后幂等地补建 `node_modules/.bin/` 下的 `mdlineage`、`mdlineage-lsp`、`mdlineage-mcp` 三个链接并补上可执行位。

构建完成后有四种调用方式，第一种永远可用：

```bash
node packages/cli/dist/main.js --version        # mdlineage 0.1.0
npx --no-install mdlineage --version            # 依赖构建补建的 bin 链接
./node_modules/.bin/mdlineage --version         # 本地 bin 路径
npm link                                        # 在 packages/cli 内执行，之后全局可用
```

`node packages/cli/dist/main.js --help` 打印完整命令参考（任何子命令加 `--help` 打印的都是同一份全局帮助，不存在按子命令定制的帮助文本）。

## 3. 五分钟快速开始

以下流程默认全部是只读或试运行，唯一写盘的动作是显式加 `--write`。

在你自己的文档仓库里：

```bash
mdlineage init          # 试运行：只打印计划，不写任何文件
mdlineage init --write  # 写入 mdlineage.config.yaml、.gitattributes、schemas/
```

`init` 是幂等的，已存在的 `.gitattributes` 只会追加缺失的行，绝不重写。真实输出：

```text
mdlineage: create mdlineage.config.yaml (metadata.required: false)
mdlineage: create .gitattributes:
mdlineage: +* text=auto eol=lf
mdlineage: create schemas/ (empty schema directory)
mdlineage: dry run, nothing written (3 changes; pass --write to apply)
```

生成的配置采用渐进式采纳：`metadata.required: false`，没有元数据的文档不会报错，等语料库逐步接入后再逐个文件打开。

写一份带元数据的文档并校验：

```bash
mdlineage check .
```

```text
mdlineage: 1 file checked, no diagnostics
```

故意写错几处再校验，观察真实报错：

```text
getting-started.md:3:3 MDL102 error Missing required mdlineage field: kind
getting-started.md:3:3 MDL102 error Missing required mdlineage field: status
getting-started.md:5:3 MDL104 error Unknown mdlineage field: tpoics
getting-started.md:11:5 MDL401 warning Markdown link target does not exist: cache-policy.md
mdlineage: 1 file checked, 4 diagnostics (3 errors, 1 warning), 0 unreadable files
```

退出码是 `1`（有 error 级诊断）。让机器修掉不需要判断的部分：

```bash
mdlineage fix            # 试运行，打印将要写入的 diff
mdlineage fix --write    # 真正落盘
```

```text
getting-started.md:7: [status] MDL102 requires 'status'; proposed from the configured vocabulary (first member of statuses).
getting-started.md:7: [kind] MDL102 requires 'kind'; proposed from the configured vocabulary (first member of kinds).
  +   status: draft
  +   kind: policy
mdlineage fix: 2 fixes in 1 file
```

重新 `check`：两个 MDL102 消失了，MDL104（拼写错误）和 MDL401（死链）仍在——`fix` 从不大改字段名或改写链接，因为这两件事需要人来决定。对于它不能猜的元数据，`suggest <file>` 给出只读的修改提议：

```bash
mdlineage suggest getting-started.md
```

```json
{
  "path": "getting-started.md",
  "operations": [
    {
      "jsonPointer": "/kind",
      "value": "policy",
      "rationale": "MDL102 requires 'kind'; proposed from the configured vocabulary (first member of kinds)."
    }
  ],
  "addresses": ["MDL102"],
  "source": "rules",
  "generator": "mdlineage/suggest_metadata/rules-v1",
  "contentHash": "7a284541f7a023b77debd22ee996adc3448b0a75bbee9525066e4ab544d34182",
  "id": null,
  "createdAt": null
}
```

存量仓库的完整采纳路径见第 9.2 节。

## 4. Front Matter 元数据契约

元数据写在每个 Markdown 文档的 `mdlineage:` 键下（键名由 `metadata.key` 配置，默认 `mdlineage`）。这是文档身份与关系的唯一事实来源；配置文件只决定规则与范围，永远不能使元数据为真或为假。

### 4.1 字段总表

| 字段 | 必填 | 约束 | 违规模诊断码 |
| --- | --- | --- | --- |
| `schema` | 是 | 固定为数字 `1` | 缺失 MDL102；非 1 报 MDL101 |
| `id` | 是 | 正则 `^[a-z0-9]+(?:[.-][a-z0-9]+)*$`，最长 128；全仓唯一 | 缺失 MDL102；格式错 MDL103；跨文件重复 MDL301 |
| `kind` | 是 | 非空；取值须在 `vocabulary.kinds` 内（默认 `policy`、`guide`、`architecture`、`reference`） | 缺失 MDL102；非法值 MDL103 |
| `status` | 是 | 非空；取值须在 `vocabulary.statuses` 内（默认 `draft`、`active`、`deprecated`） | 缺失 MDL102；非法值 MDL103 |
| `authority` | 否 | 非空；取值须在 `vocabulary.authorities` 内（默认 `canonical`、`supporting`） | 非法值 MDL103 |
| `topics` | 否 | 字符串数组，元素非空 | 非法元素 MDL103 |
| `aliases` | 否 | 字符串数组，元素非空，可含中文 | 非法元素 MDL103 |
| `relations` | 否 | 关系对象数组，同文档内不得逐字节重复 | 重复 MDL202 |

关系条目子字段：

| 子字段 | 必填 | 约束 |
| --- | --- | --- |
| `type` | 是 | 七种类型之一：`depends_on`、`implements`、`refines`、`supersedes`、`contradicts`、`example_of`、`related_to` |
| `target` | 是 | 目标文档的 `id`（**不是文件路径**），格式同 `id` |
| `reason` | 强关系必填 | 1–512 字符；强关系整体缺失报 MDL102，存在但为空报 MDL304 |
| `evidence` | 否 | 形如 `"#anchor"`，解析自**目标**文档的标题；格式错 MDL103，当前文档找不到报 MDL201，目标文档找不到报 MDL402 |

`mdlineage` 对象内出现任何未定义键（含拼写错误，如 `tpoics`）一律报 MDL104——schema 的 `additionalProperties: false` 是写死的。顶层（`mdlineage` 之外）的未知字段由其他工具写入，始终保留、从不诊断。

### 4.2 完整示例

```yaml
---
mdlineage:
  schema: 1
  id: docs.cache-policy
  kind: policy
  status: active
  authority: canonical
  topics:
    - caching
    - security
  aliases:
    - cache TTL
    - 缓存有效期
  relations:
    - type: depends_on
      target: docs.authentication-model
      reason: Cache keys include account identity and permission scope.
      evidence: "#cache-key"
---
```

反向的关系书写在另一篇文档里，绝不在此处复制——反向引用由索引派生生成：

```yaml
# docs/high-risk-account-policy.md
relations:
  - type: refines
    target: docs.cache-policy
    reason: High-risk accounts have a shorter cache lifetime.
    evidence: "#high-risk-accounts"
```

仓库的 `test/fixtures/` 下有 27 个验收夹具（6 个 valid、17 个 invalid、4 个 workspace），`manifest.json` 是每个夹具必须产出的诊断码契约，`README.md` 说明了各夹具的用意。

### 4.3 七种关系类型

方向固定为 `A <type> B`，不可按关系单独配置。默认开关如下（可在 `mdlineage.config.yaml` 的 `relations` 中调整）：

| 类型 | 含义 | impact | reasonRequired | selfReference | cycles |
| --- | --- | --- | --- | --- | --- |
| `depends_on` | A 依赖 B 的规则或事实 | 是 | 是 | forbidden | allowed |
| `implements` | A 记录对 B 的实现 | 是 | 是 | allowed | allowed |
| `refines` | A 细化或补充 B | 是 | 是 | allowed | allowed |
| `supersedes` | A 取代 B 成为现行基准 | 是 | 是 | allowed | **forbidden** |
| `contradicts` | A 与 B 的主张看似冲突，需人工审阅 | — | 是 | allowed | allowed |
| `example_of` | A 是 B 的实例 | 否 | 否 | allowed | allowed |
| `related_to` | 宽泛的主题关联，仅用于发现 | 否 | 否 | allowed | allowed |

`impact` 驱动派生层的影响分析，本身不产生诊断。`cycles: forbidden` 触发 MDL305（按强连通分量报告，每个环只报一次，锚定在字典序最小的路径上）。`selfReference: forbidden` 触发 MDL103。`contradicts` 的默认严重级别是 warning，其余为 error。

## 5. mdlineage.config.yaml 配置参考

配置文件是声明式、不可执行的数据：它只声明规则与范围，不携带任何文档身份与关系。删掉全部配置文件，语料库本身仍然成立。

### 5.1 配置如何被找到

- `check`、`fix`、`suggest` 从当前目录**向上**查找 `mdlineage.config.yaml`，子目录里运行也能找到根配置；向上查找可能越过 git 根。
- `--config <path>` 显式指定。隐式找不到配置是合法状态（静默应用内置默认值）；显式指定的路径不存在则是错误（MDL900，退出码 1）。
- 配置解析失败或过不了 schema：报 MDL900，回退内置默认值，文档校验继续——坏配置永远不会阻断语料库。

### 5.2 顶层键总表

只有 `configVersion` 必填（必须为 `1`），其余全部可选。默认值来自 `defaultConfig()`（`packages/validator/src/config.ts`）与 `schemas/mdlineage-config.schema.json`。

| 键 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `configVersion` | number | —（必填，须为 1） | 配置模式版本，其他值报 MDL900 |
| `files.include` | string[] | `['**/*.md']` | 工作区扫描的候选 glob |
| `files.exclude` | string[] | `['node_modules/**', 'dist/**', 'vendor/**']` | 排除 glob；CLI、LSP 与 MCP 扫描均遵守此配置 |
| `files.followSymlinks` | boolean | `true` | 是否跟随符号链接遍历目录与解析子文档 |
| `files.symlinkMaxDepth` | number | `10` | 符号链接遍历的最大嵌套跳数上限 |
| `manifestFile` | string | 无 | 外部旁路元数据清单 YAML 相对路径（方案四） |
| `manifest` | object | 无 | 内联旁路元数据清单（含 `documents` 映射） |
| `links.expandTilde` | boolean | `true` | 是否将链接目标中的 `~` 与 `$HOME` 展开为宿主机路径 |
| `links.allowHostPaths` | `always`\|`warning`\|`forbidden` | `warning` | 宿主机跨机路径的容忍策略（MDL403） |
| `metadata.key` | string | `mdlineage` | Front Matter 中存放元数据的键名 |
| `metadata.required` | boolean | `true` | 文档缺元数据时报 MDL003；`false` 全仓抑制；`true` 时可由 layout 的 `require.frontmatter: optional` 或旁路清单豁免 |
| `metadata.preserveUnknownTopLevelFields` | boolean | `true` | 声明保留其他工具写的顶层字段；**无规则消费** |
| `metadata.rejectUnknownMdlineageFields` | boolean | `true` | 声明拒绝 `mdlineage` 内未知键；**无规则消费**（MDL104 由 schema 写死，设 `false` 也不会放松） |
| `vocabulary.kinds` | string[] | `['policy', 'guide', 'architecture', 'reference']` | 合法 `kind` 值，非法值 MDL103 |
| `vocabulary.statuses` | string[] | `['draft', 'active', 'deprecated']` | 合法 `status` 值 |
| `vocabulary.authorities` | string[] | `['canonical', 'supporting']` | 合法 `authority` 值 |
| `relations.<type>` | object | 见 4.3 节 | 每种关系的 `impact`/`reasonRequired`/`selfReference`/`cycles`/`severity` 开关 |
| `lifecycle` | object | 见 5.3 节 | 废弃依赖拦截（MDL306）与时效治理（MDL801） |
| `diagnostics` | object | 码表默认值 | 按诊断码覆盖严重级别（`error`/`warning`/`information`/`hint`） |
| `eolPolicy` | `lf`/`crlf`/`cr` | `lf` | 行尾策略，驱动 MDL602 与 `init` 写的 `.gitattributes` 行 |
| `extends` | string[] | 无 | 组织预设（见 5.4） |
| `schemaFile` | string | 无 | 指向仓库自定义元数据 schema；扩展自定义字段并校验 |
| `layout` | array | 无 | 目录规范（MDL501）与目录意图契约（见 5.5，MDL502/MDL504） |
| `layoutExceptions` | array | 无 | 目录规范带时效的豁免例外（见 5.5，MDL503） |
| `policies` | object | 无 | 仓库策略 DSL；**保留未实现** |

顶层未知键会被 `additionalProperties: false` 拦截为 MDL900——`diagnostic:` 这样的拼写错误不会静默通过。

### 5.3 关键行为与生命周期配置

- **`lifecycle` 时效与废弃拦截**：
  - `activeStatuses`: `['active']`（空数组关闭 MDL306）。
  - `deprecatedStatuses`: `['deprecated']`。
  - `blockingRelations`: `['depends_on', 'implements', 'refines']`（默认故意不含 `supersedes`，以便写迁移更替文档）。
  - `staleAfterDays`: 整数（`0` 关闭 MDL801）。
  - `staleStatuses`: `['active']`。
  - `exempt`: 豁免路径 glob 数组（如 `['archive/**', 'docs/archive/**']`）。
  - 时钟优先级：手写 `updated_at` → 手写 `created_at` → Git 提交历史批量回退；`reviewed_at` 不算时钟。
- **`relations` 下某类型一旦被命名就整体替换默认值，不按键合并。** 写 `relations: {contradicts: {severity: error}}` 会静默丢掉 `contradicts` 自带的 `reasonRequired: true`，MDL304 对它不再触发。未提及的类型保持默认。

`diagnostics` 覆盖可以直接改变 `check` 的退出码：把 warning 提升为 error，无需改动任何文档即可让 CI 变红。remark 通道会把 `information`/`hint` 塌缩成 warning（unified lint 只有三档），专用 LSP 则四档一一对应。

### 5.4 extends：组织预设

`extends` 是预设文件或包名数组，用于跨仓库共享组织规则而无需各自 fork：

- **解析**：含路径分隔符（`./`、`../`、`/`）的名字相对当前配置文件所在目录解析；裸名解析为 `node_modules/<name>/mdlineage.config.yaml`。注意 POSIX 上 `@acme/preset` 这类带作用域的名字含 `/`，会被当作相对路径。
- **合并顺序**：预设先合并、数组按序后者胜出，最后当前文件自己的键覆盖预设；映射（`relations`、`metadata`、`diagnostics`、`vocabulary`）按键递归合并，数组与标量整体替换（预设的 `statuses` 不会与仓库的取并集）。预设自身也可以 `extends`，任意深度。
- **环是硬拒绝**：`a extends b extends a` 报 MDL900 `Circular extends: ...`，配置回退默认值。预设缺失同样报 MDL900 并回退。

该机制在 `packages/validator/test/validator.test.ts` 的 `config extends` 测试块中有 6 个用例覆盖（单预设、本地覆盖、多预设按序、环拒绝、缺失、多级链）。

### 5.5 layout 目录意图契约与例外机制（P4）

`layout` 规则将目录路径声明与文档类型意图绑定，使目录拓扑具备机器可校验的契约：

```yaml
layout:
  - match: '**/*.md'
    require:
      frontmatter: optional
  - match: 'docs/guides/**'
    intent:
      description: 操作指南与实践手册
      kinds: [guide]
      naming: '^[a-z0-9-]+$'
      maxDepth: 2

layoutExceptions:
  - path: 'docs/guides/legacy-tool.md'
    reason: 待迁移至 reference/ 目录
    expires: '2026-12-31'
```

- **意图字段**：
  - `kinds`: 目录允许的文档类型数组，违背报 **MDL502**（`directory-misplaced`）。
  - `naming`: 文件名正则模式（不含扩展名），不匹配报 **MDL504**（`layout-constraint`）。
  - `maxDepth`: 相对匹配前缀的目录最大嵌套层级，超限报 **MDL504**。
  - `forbidStatus`: 目录禁止的生命周期状态。
- **例外机制（`layoutExceptions`）**：
  为存量过渡期文档提供白名单豁免；声明 `expires`（格式 `YYYY-MM-DD`）的例外一旦超过当前日期，豁免自动失效并报 **MDL503**（`exception-expired`，严重级别 error）。

### 5.6 方案四：旁路元数据清单（Out-of-band Manifest）

针对外部共享仓库、符号链接目录（如多 Agent 共享的技能库）或严禁改动正文的 Markdown 文档，MDLineage 提供了**零修改正文（Zero-touch）**的旁路元数据映射方案。

#### 核心原理
元数据不在 Markdown 文件的 Front Matter 中书写，而是收敛至外部清单文件（或配置文件内联声明）。MDLineage 在扫描时将正文内容与外部清单在内存中拼装为一等公民的 `DocEntry`：

```yaml
# mdlineage.config.yaml
configVersion: 1
manifestFile: mdlineage.manifest.yaml # 外部清单相对路径
```

```yaml
# mdlineage.manifest.yaml
version: 1
documents:
  skills/paper-reader/SKILL.md:
    id: skill.paper-reader
    kind: reference
    status: active
    relations:
      - type: depends_on
        target: skill.word-extractor
        reason: 提取 docx 题注与正文结构
```

- **零字节修改**：物理 Markdown 文件保持只读，Git 零污染，消除多客户端（如 Claude Code / DSH / Cursor）间的 Front Matter 字段冲突。
- **完整图谱能力**：清单注入的文档自动豁免 **MDL003**，且全量参与 **MDL301**（重复 ID）、**MDL302**（悬空目标）、**MDL305**（循环依赖）、**MDL306**（废弃依赖）校验与 `WorkspaceIndex` 反向依赖反查。

### 5.7 Linux 宿主链接与符号链接穿透策略

知识库广泛存在 Shell 风格路径（`~/...`）与跨目录软链接，MDLineage 提供两项专项扩展：

- **`links` 策略配置**：
  - `expandTilde: true`（默认开启）：自动将超链接目标中的 `~` 与 `$HOME` 展开为宿主机绝对物理路径。
  - `allowHostPaths`:
    - `warning`（默认）：宿主机物理文件不存在报 **MDL403 warning**；存在但位于外部报不可移植 warning；存在且位于当前工作区内则给出相对路径建议。
    - `always`：宿主机文件只要存在即完全静默放行（0 诊断）。
    - `forbidden`：任何宿主路径直接报 **MDL403 error**（适合严格的跨机 CI 沙箱）。
- **`files.followSymlinks` 与环路拦截**：
  - 默认开启（`followSymlinks: true`），配合 `symlinkMaxDepth: 10`。
  - 扫描器采用逻辑路径投影模型，底层以 `realpathSync` 物理集合做 $O(1)$ 的自环（`a -> b -> a`）与重复遍历拦截，安全穿透深层参考子目录。

## 6. CLI 命令参考

### 6.1 通用约定

退出码契约，全部子命令一致：

| 退出码 | 含义 |
| --- | --- |
| 0 | 无 error 级诊断（含配置缺失但合法、试运行成功等） |
| 1 | 至少一个 error：诊断、文件不可读、`--config` 损坏、路径逃逸等；`--frail` 时任意级别诊断也算 |
| 2 | 用法错误：未知选项、未知传输、非法的 `--format` 值、路径匹配不到任何文件、git 仓库外使用 `--changed` |

根锚定，各命令刻意不同：

| 命令 | 工作区根 |
| --- | --- |
| `check`、`fix` | CWD；`fix` 拒绝解析到 CWD 之外的路径 |
| `baseline`、`init` | git 仓库根（不在 git 仓库则退回 CWD）——二者都是仓库级契约 |
| 配置查找 | 从 CWD 向上走查 |

常用全局选项：`--format <text|json|sarif>`（默认 text）、`--config <path>`、`--changed`、`--no-untracked`、`--exclude <pattern>`（可重复）、`--no-incremental`、`--no-baseline`、`--frail`、`--write`、`--force`、`--report-only`、`--root <dir>`（仅 `mcp`）、`--help/-h`、`--version/-v`。`init` 显式拒绝 `--config`（退出码 2）。

### 6.2 check

```bash
mdlineage check [paths...]        # 默认校验 CWD
mdlineage check --changed         # 只校验 git status 报告的变动文件
mdlineage check docs              # 校验子目录（注意 10.1 节的快照语义）
```

权威校验：先逐文档校验，再由跨文件规则补充 MDL301（重复 id）、MDL302（悬空目标）、MDL305（禁止环）、MDL401（死链）、MDL402（跨文档锚点）。

`--changed` 通过 `git status --porcelain` 取变动文件、按工作树真实字节比对——`.gitattributes` 生效时，纯行尾改动的 `git diff` 为空但工作树字节不同，`--changed` 正是为这个场景设计的。未跟踪文件默认包含，`--no-untracked` 跳过。没有变动 Markdown 时如实报告并退出 0。不在 git 仓库中使用退出码 2。

三种输出格式：

- **text**（默认）：`path:line:column CODE severity message`，每诊断一行加汇总行；配置诊断走 stderr。
- **json**：`check` 输出 `reports`、`unreadable`、`configDiagnostics`、`baseline`、`summary` 五个键；`summary` 含 `files`、`errors`、`warnings`、`information`、`unreadable`、`byCode`。`config validate` 输出 `{source, diagnostics}`，`index rebuild` 输出 `{stats: {files, ids, relations, anchors}, diagnostics}`。配置诊断在任何格式下都走 stderr，只消费 stdout 的 JSON 客户端无需分流两个流。
- **sarif**：仅 `check` 支持，SARIF 2.1.0；`information` 与 `hint` 都映射到 SARIF `note` 级，`properties.mdlineageSeverity` 保留原值。

`--no-incremental` 完全关闭跨文件规则，退化为逐文件独立校验。`--no-baseline` 忽略基线，把被压制的历史债务全部暴露。`--frail` 让任意级别诊断都退出 1（本仓库的 remark 门禁用的就是它）。

### 6.3 baseline

```bash
mdlineage baseline update [--report-only] [--force]
mdlineage baseline show
mdlineage baseline verify
```

基线是仓库根目录下**提交进 git** 的 `.mdlineage-baseline.json`（version 1，含 `generatedAt` 与按码分组的路径），不是本地缓存。它让中途采纳 MDLineage 的仓库先落地绿灯、再逐步收紧。

- `update` 永远跑全量工作区（绝不用 `--changed` 子集——用子集写出的契约会悄悄豁免子集之外的一切），把当前违规合并进基线。`--report-only` 只打印变更集；现有基线损坏且未读出来时拒绝覆盖（会丢失已接受的豁免），`--force` 才强制写。
- `show` 按码列出条目数。
- `verify` 是 CI 门禁：当前诊断与基线**精确一致**才退出 0——不容忍新违规，也不容忍陈旧条目。陈旧条目是“已还清的债”，必须手工从基线文件里删掉那一行，因为一个陈旧豁免可能日后掩护重新引入的同一违规。

标记语义：`+` 新违规、`-` 文件中确实不再违、`~` 陈旧（`update` 故意保留）。

本仓库实测：`show` 报 21 条，`verify` 报 23 条——二者不矛盾。基线按 `(码, 路径)` 记账，共 21 个条目；而同一文件同一码可以命中多处（如 `e04` 命中 2 次 MDL104、`e07` 命中 2 次 MDL102），抑制按码与路径匹配，所以被抑制的诊断总数是 23。

```text
$ mdlineage baseline show
mdlineage: baseline /home/dc/projects/md-lineage/.mdlineage-baseline.json (version 1)
generated at 2026-09-22T13:44:54.994Z
  MDL001 1
  MDL102 3
  MDL103 5
  ...
total 21 accepted violations

$ mdlineage baseline verify
mdlineage: baseline verified, 23 accepted violations
```

### 6.4 init

引导仓库：写 `mdlineage.config.yaml`（`metadata.required: false`）、`.gitattributes`（行内容跟随 `eolPolicy`：`lf` 写 `* text=auto eol=lf`，`crlf` 写 `* text=auto eol=crlf`，`cr` 写 `* text=auto`，因为 git 的 `eol` 属性没有 CR 形式）、空的 `schemas/` 目录。默认试运行，`--write` 落盘；已存在的 `.gitattributes` 只追加缺失行；目标不可写时报名报错（退出码 1，无堆栈）。

### 6.5 fix

只应用无需判断的修复，共四类：

1. **MDL102**：插入缺失字段，从配置词汇表取首个合法值；关系的 `reason` 是例外，插入占位符 `TODO: explain this relationship (proposed by mdlineage)`。
2. **MDL202**：删除同文档内逐字节重复的关系条目。
3. **MDL103**：当枚举值在词汇表中有**唯一**的大小写不敏感匹配时规范化；多项匹配时报错并留给人工。
4. **MDL601/MDL602**：把整个文件的行尾规范化到配置策略。

它从不动 `id`、关系的 `type`/`target`、未知字段的值。写入是原子的（同目录临时文件加 rename）。路径解析到 CWD 之外一律拒绝（退出码 1）。默认试运行，`--write` 落盘。实测：

```text
$ mdlineage fix a.md
a.md:9: [reason] MDL102 requires a reason on relation #0; a strong relation type is not valid without one.
  +       reason: "TODO: explain this relationship (proposed by mdlineage)"
mdlineage fix: would fix 1 issue in 1 file (dry run; use --write to apply)
```

### 6.6 suggest

只读。打印 MCP `suggest_metadata` 会返回的提案 JSON（含 `operations`、`addresses`、`contentHash`，`id`/`createdAt` 为 `null`——CLI 进程是一次性建议，没有可接受的队列），从不写盘。

### 6.7 config validate

```bash
mdlineage config validate [--format text|json]
```

只校验配置本身：合法打印 `mdlineage: config OK (<path>)` 退出 0；不合法打印 MDL900（格式与 `check` 一致）退出 1。**没有配置文件是合法状态**（退出 0，应用默认值）；显式 `--config` 指向不存在的文件则失败。本命令只接受 text 与 json，`--format sarif` 退出码 2。

### 6.8 index rebuild

```bash
mdlineage index rebuild [--format text|json]
```

扫描工作区，在内存中重建图索引，报告统计与索引级诊断；**什么都不持久化**——索引是派生数据，按需重建。本仓库实测：

```text
mdlineage: index rebuilt: 46 files, 39 ids, 14 relations, 328 anchors, 23 diagnostics (18 errors), not persisted
```

### 6.9 server 与 mcp

```bash
mdlineage server --stdio   # 专用语言服务器
mdlineage mcp --stdio      # MCP 服务器，可用 --root <dir> 指定索引的树（默认 CWD）
```

两者接管 stdin/stdout 做 JSON-RPC，启动前不打印任何东西。`--stdio` 是唯一传输；省略或写 `--http` 之类是用法错误（退出码 2）。注意：`mdlineage server --stdio` 走 CLI 入口时只接受 `--config`，`--root` 只对 `mcp` 生效；要给 LSP 指定根目录，需直接运行 `node packages/language-server/dist/server-entry.js --stdio --root <dir>`，或让客户端在 LSP `initialize` 握手时给出 `workspaceFolders`（或旧式的 `rootUri`/`rootPath`）。

### 6.10 move

单文档安全移动与级联链接自愈重构：

```bash
mdlineage move <src> <dst>           # 试运行（默认）：打印规划与受影响引用，零写盘
mdlineage move <src> <dst> --write   # 真正执行移动与全仓链接自愈
```

- **原子化链接自愈**：
  - 自动遍历全仓所有指向 `src` 的引用方（入边），根据新路径深度与目录关系精确重写相对路径（包含保留原始 `#anchor` 锚点）。
  - 文档自身包含的指向外部资源与图片的相对链接（出边），根据新目录层级自动重新计算相对路径。
- **历史延续与时钟刷新**：优先调用 `git mv` 保持 Git 提交历史；若包含 Front Matter，自动将 `updated_at` 刷新为当前日期。
- **安全防护**：目标物理文件已存在时拒绝覆盖；配置存在 error 级诊断时终止操作。

### 6.11 organize

目录规范批量治理与全局重组：

```bash
mdlineage organize --inventory       # 盘点：统计全仓文档的类别(kind)分布、目录分布与未纳管孤儿文档
mdlineage organize --report          # 报告：评估目录 intent 规范合规率与例外统计
mdlineage organize --plan            # 规划：结合 layout.intent 检测错位文档，输出批量迁移建议与影响面
mdlineage organize --apply           # 执行：批量应用重构迁移方案，执行全仓相对链接自愈更新
```

- 可选 `--scope <glob>` 参数将整理范围限制在指定的子目录或模式内。
- 批量执行时采用动态快照迭代算法，避免同一引用方被多次移动写盘时发生覆盖丢失。

## 7. 诊断码完整参考

### 7.1 谁能报哪些码

单文档规则只需要文件本身；跨文件规则需要包含每个文档 id 与每条路径的工作区快照。这是最常见的困惑来源：单独校验一个文件时，跨文件问题（如重复 id）根本不可见。

| 入口 | 层 | 可报的码 |
| --- | --- | --- |
| remark 插件 | 单文档 | MDL001–003、MDL101–104、MDL201–203、MDL501–504、MDL601、MDL602、MDL801（外加 MDL900 配置诊断） |
| `check <file> --no-incremental`、MCP `validate_document` | 单文档 | 同上 |
| `check .`、`index rebuild`、LSP、MCP `validate_repository` | 工作区 | 上述全部 + MDL301–306、MDL401–403、MDL505、MDL801（Git 时钟） |

例外：`check <单文件>` **不带** `--no-incremental` 时仍会跑跨文件规则，但快照里只有这一个文件——兄弟文档里的目标会被误报为 MDL302/MDL401。把这类结果当作提示而非结论；校验子目录同理，快照只含被匹配的文件。

## 8. 四条集成通道

一个校验核心，四种触达方式。同一缓冲区上同时启用多个 lint 通道会得到重复诊断，选一个。

### 8.1 通道 A：remark 插件

适合已经使用 remark 工具链的编辑器。在 `.remarkrc.mjs` 中接线（顺序有讲究，`remark-frontmatter` 必须在插件之前，它把 Front Matter 保留在内存 VFile 里，未保存的缓冲区因此也能校验）：

```javascript
import remarkFrontmatter from 'remark-frontmatter'
import remarkGfm from 'remark-gfm'
import remarkPresetLintRecommended from 'remark-preset-lint-recommended'
import remarkLintMdlineage from '@mdlineage/remark-lint-mdlineage'

export default {
  plugins: [
    remarkGfm,
    [remarkFrontmatter, ['yaml']],
    remarkPresetLintRecommended,
    [remarkLintMdlineage, { configFile: './mdlineage.config.yaml' }],
    // unified-lint-rule 会把 error 级消息降级为 warning，这个转换器按
    // data.mdlSeverity 恢复真实严重级别
    remarkLintMdlineage.restoreSeverity
  ]
}
```

限制：unified lint 只有 0/1/2 三档，`information` 与 `hint` 在此通道塌缩为 warning；多行 YAML 结构编辑类的快速修复不可用。VS Code 装 `vscode-remark` 扩展即可，配 `"remark.requireConfig": true` 让没有 `.remarkrc.*` 的仓库被整体跳过，避免个人插件产出与 CI 不同的诊断。其他编辑器可注册 `remark-language-server --stdio` 客户端。

### 8.2 通道 B：专用 LSP

```bash
mdlineage server --stdio        # 或 node packages/language-server/dist/server-entry.js --stdio
```

一次 `initialize` 握手实测宣告的能力：

```text
textDocument.synchronization: { openClose: true, change: 2 (incremental), save: { includeText: false } }
textDocument.completion:      triggerCharacters [":", " "], resolveProvider: false
textDocument.definition / references / hover
textDocument.rename:          prepareSupport: true
textDocument.documentSymbol:  hierarchicalDocumentSymbolSupport: true
textDocument.codeAction:      kinds ["quickfix"], resolveProvider: false
workspace.workspaceFolders:   supported: true, changeNotifications: true
workspace.symbol
```

具体行为：补全覆盖关系 `type`、全工作区文档 id、目标文档标题锚点、`kind`/`status`/`authority` 枚举与顶层字段名；悬停展示关系类型释义与目标文档路径；`target`/`id` 上可跳定义、查引用；重命名只允许在 `id` 声明处发起，新 id 非法或已被占用会被拒绝；快速修复覆盖 MDL104（删除未知标量字段）、MDL102（插入缺失字段骨架）、MDL202（删除重复关系块）。200ms 去抖；超过 2MB 的文档跳过校验并提示；单文件修改后只重报受影响的引用方。

工作区解析优先 `workspaceFolders`，兼容 `rootUri`/`rootPath`；指向文件时取其父目录，指向不存在的路径则忽略该提示。`initialize` 确定根后会重新从真实根加载配置与基线。

VS Code 无随包扩展，用通用 LSP 客户端扩展启动 `node <repo>/packages/language-server/dist/server-entry.js --stdio`；Neovim 用 `vim.lsp.start`，`cmd` 指向同一入口，`root_dir` 用 `.git`/`mdlineage.config.yaml` 向上查找。

### 8.3 通道 C：MCP 服务器

```bash
mdlineage mcp --stdio --root <dir>    # --root 默认 CWD
```

七个工具：

| 工具 | 入参 | 行为 |
| --- | --- | --- |
| `validate_document` | `path`（必填）、`content?`（可选） | 单文档校验；传 `content` 则校验未保存的内存文本，不读盘 |
| `validate_repository` | `paths?`（可选） | 全仓校验，含跨文件码；自动应用基线抑制 |
| `get_schema` | `version?`（仅支持 1） | 返回元数据 JSON Schema，供模型生成 Front Matter 前参考 |
| `list_document_ids` | `query?`、`kind?`、`status?` | 枚举工作区文档 id/路径/kind/status；关系 target 必须是 id，写关系前用它查 |
| `resolve_relation_target` | `id`（必填） | 把 id 反解为路径，返回 `unique`/`unresolved`/`ambiguous` 及引用方列表 |
| `suggest_metadata` | `path`（必填）、`content?`（可选） | 只读分析，生成确定性提案并入内存队列，返回 `proposal.id` |
| `apply_metadata_patch` | `proposal_id`（必填）、`write?`（默认 false） | 应用提案；默认只返回 TextEdits、`patchedContent` 与 LCS diff，不写盘 |

另暴露两个只读资源：`urn:mdlineage:schema:mdlineage-v1` 与 `urn:mdlineage:schema:mdlineage-config`。

写盘边界：`apply_metadata_patch` 默认纯内存。只有显式 `write: true` 才落盘，且要过四重守卫——目标不得逃出工作区根（realpath 全链路展开，防符号链接逃逸）；提案时在盘上的文件不得已被删除或改名；磁盘内容哈希必须仍与提案时一致（防覆盖他人编辑）；写入经临时文件原子 rename，写前复核目标未在瞬间变成符号链接。任一守卫拒绝时文件原样保留，提案自动重新入队并返回新的 `requeuedProposalId`。注意提案 id 是内存态的，服务器重启即失效，`suggest` 与 `apply` 必须在同一会话内完成；`suggest_metadata` 返回的键是 `id`，`apply_metadata_patch` 的入参名是 `proposal_id`，需要调用方做一次映射。

客户端配置（Claude Desktop / Claude Code 风格，替换路径）：

```json
{
  "mcpServers": {
    "mdlineage": {
      "command": "node",
      "args": ["<repo>/packages/cli/dist/main.js", "mcp", "--stdio", "--root", "<repo>"]
    }
  }
}
```

仓库自带冒烟脚本，从根目录运行：

```bash
node mcp-stdio-smoke.mjs packages/mcp-server/dist/entry.js
```

它会以真实 stdio 连接服务器、列出七个工具并对夹具调用 `validate_document`。

## 9. CI 与门禁

### 9.1 hygiene gates

`.github/workflows/ci.yml` 的 `gates` job 跑三项检查，另有一个 Node 20/22 矩阵跑 `npm ci && npm run build && npm test`。三项门禁（本机实测全绿）：

1. **行尾**：`git ls-files --eol` 找出 `w/crlf` 或 `w/mixed` 的工作树文件（`.gitattributes` 标记 `-text` 的两个 EOL 夹具豁免），有则失败。
2. **基线**：`mdlineage baseline verify`，当前诊断与提交的基线必须精确一致（本仓库 23 条已接受违规）。
3. **Markdown lint**：`npm run lint:md`（即 `remark docs README.md --frail --no-stdout`），任何 warning 都失败。

截至 2026-09-24，CI 已在 GitHub 实际运行过 4 次，HEAD（`15f216f`）三个检查全部 success；README 中“CI has never run”的表述已经过时。

### 9.2 存量仓库的采纳序列

```bash
mdlineage check . --no-baseline   # 看原始债务，什么都不压制
mdlineage baseline update         # 记录为已接受
git add .mdlineage-baseline.json  # 基线是提交进仓库的契约，不是本地缓存
```

此后 `check .` 把豁免的违规报为已解决，CI 门禁是 `mdlineage baseline verify`：只有诊断与基线精确一致才退出 0。无基线且无诊断退出 0（干净采纳）；无基线但有违规退出 1——门禁不会让未豁免的仓库蒙混过关。永远不要把 `--no-baseline` 的输出接进 CI：基线才是契约。

## 10. 过时文档与损坏前置依赖的发现流程（四阶段漏斗管线）

在知识库工程中，排查文档过时与依赖断裂不需要逐篇全文通读。人工通读成本高昂且极易漏掉深层级联依赖。MDLineage 推荐采用漏斗式的自动化检测管线，在数秒内将全仓数百篇文档收敛至极少数异常靶点：

### 10.1 第一阶段：静态规则与时钟秒级快筛（全量机器筛查）

运行 `mdlineage check . --format json`，让校验器执行 AST 语法树解析、超链接验证与生命周期时钟计算：

1. **前置依赖损坏（Broken Prerequisites）**：
   - **MDL302（关系目标丢失）**：文档声明了 `depends_on: A`，但全仓不存在 ID 为 `A` 的文档。
   - **MDL306（依赖已废弃）**：当前活跃文档依赖的底层模块或前置规范已被标记为 `deprecated` 或 `archived`。
   - **MDL401 / MDL403（链接目标失效）**：文档正文中引用的相对路径或宿主路径在磁盘上物理不存在。
2. **生命周期超期（Freshness Decay）**：
   - **MDL801（时钟超期报警）**：根据配置的 `lifecycle.staleAfterDays`（如 30、90 或 180 天），由系统比对 Front Matter 的 `updated_at`（或 Git 提交历史），自动筛选出超过维护周期的文档。
   - **MDL503（过渡期例外过期）**：之前通过 `layoutExceptions` 登记的临时兼容项，一旦到达 `expires` 截止日期自动报错。

### 10.2 第二阶段：拓扑图谱与级联影响面分析（DAG 反向推理）

利用 MDLineage 内存中的 `WorkspaceIndex` 关系网络进行图算法分析：

1. **孤岛文档探测（Orphan Detection）**：
   - 遍历图谱，统计入度（被引用数）与出度（引用外部数）。
   - 零入度且零出度的叶子文档（或触发 **MDL505** 的散落文档）通常是历史上创建后被遗忘的残留文件，属于重点排查对象。
2. **变更爆炸半径追踪（Blast Radius Traversal）**：
   - 当某个底层设计或前置规范发生变动或废弃时，无需翻看所有文档。
   - 调用 `index.referrersOf(targetId)`，直接提取整个依赖树上的所有下游直接与间接引用方，只对这批受影响的文档进行定向复核。

### 10.3 第三阶段：事实实体与环境探针扫描（外在事实比对）

针对文档正文中描述的外部客观事实漂移（如记录的软件版本过低、服务端口变更、物理文件路径迁移）：

1. **实体批量抽取**：通过工具从正文中提取包含硬编码事实的模式（如代码块、版本号 `vX.Y.Z`、端口号 `:\d+`、宿主路径 `~/...`）。
2. **执行终端只读探针**：
   - 提取的路径批量执行 `test -e <path>` 验证文件系统。
   - 提取的 CLI 工具命令执行 `which <tool>`、`<tool> --version` 验证真实环境。
   - 提取的服务端口执行探测，验证运行状态。

机器会自动产出“文档宣称 v1.6.0，系统实际为 v1.6.1”或“文档宣称路径存在，实测磁盘已移走”的客观差异列表。

### 10.4 第四阶段：精准靶向语义核对（仅读异常点）

在前三阶段自动化过滤后，全仓文档已被收敛为一张清晰的待审查清单。

此时只需打开被标记的极少数文档，根据机器提供的准确定位（文件、行号、触发的诊断码）进行语义复核：
- 确认该文档是应当直接归档（切换 `status: archived`）、删除，还是需要同步最新内容；
- 刷新 `updated_at` 时间戳并补齐关联关系。

## 11. 常见陷阱与 FAQ

### 11.1 单文件 check 的假阳性

`check some-file.md` 会跑跨文件规则，但快照里只有这一个文件，兄弟文档里的关系目标与链接目标因此报 MDL302/MDL401。校验子目录同理——快照只含被匹配的文件。要可信的跨文件结论就校验目录（`check .`）；只想要单文件语法结论就加 `--no-incremental`。

### 11.2 --exclude 恢复不了默认排除

`--exclude` 是追加在内置 `node_modules/**`、`**/dist/**` 之后，不能把被默认排除的目录放回来。传了与默认排除冲突的模式时，CLI 会在 stderr 提示没有文件被检查。

### 11.3 warning 为什么不进 CI

默认只有 error 让 `check` 退出 1。需要任何诊断都失败时传 `--frail`（本仓库的 remark 门禁即如此）。

### 11.4 --changed 报告了 git diff 为空的文件

它按 `git status --porcelain` 的工作树字节比对，不看 `git diff`。`.gitattributes` 归一化索引后，纯行尾改动对 `git diff` 不可见，但工作树字节确实不同——这正是 MDLineage 要抓的场景。

### 11.5 fix 修了缺失字段，却不动拼写错误

改名是判断题，所以只进 `suggest`/MCP 提案，绝不自动应用。能无人值守运行的只有：插入缺失字段、删除逐字节重复的关系、无歧义的枚举规范化、行尾归一化。

### 11.6 基线计数 21 与 23

见 6.3 节：`show` 数基线条目（按码与路径记账），`verify` 数被抑制的诊断数（同文件同码的多处命中各计一次）。

### 11.7 MCP 提案在重启后失效

提案 id 在内存队列里；重启后重新 `suggest_metadata`。`write: true` 被拒时检查四重守卫：目标在工作区内（无符号链接逃逸）、文件在盘上、文件可写、文件自提案以来未被改动。

### 11.8 退出码 2 并打印了完整帮助

用法错误——未知命令、未知选项、非法的 `--format`、路径匹配不到文件，或 git 仓库外使用 `--changed`。原因在帮助文本的上一行，它从不是诊断。

## 12. 已知限制与未实现项

- **`metadata.rejectUnknownMdlineageFields` 与 `metadata.preserveUnknownTopLevelFields` 无规则消费**：MDL104 由 schema 的 `additionalProperties: false` 写死，设 `false` 不放松。
- **`relations.<type>.severity` 无规则消费**：改严重级别请用 `diagnostics` 块。
- **MDL303 结构性不可达**：纯 id 解析加 MDL301 唯一性保证下，目标要么 0 个（MDL302）要么 1 个，不会歧义。
- **MDL401 已知假阳性**：指向真实目录的链接（如 `./sub/`，不会回退 `README.md`/`index.md`）和百分号编码目标（如 `my%20file.md`，未做 `decodeURIComponent`）仍会误报。
- **语义检索与关系推断未开始**：P1 的后半段（向量检索、主动候选关系）属于后续阶段。
- **编码检查未实现**：BOM 与非 UTF-8 检测在 MDL6xx 扩展里编号待定。
- **LSP 与 MCP 未在真实客户端中验证**：测试与冒烟脚本只覆盖 stdio 协议本身；编辑器配置是“按协议应当可用”，未经具体客户端确认。
