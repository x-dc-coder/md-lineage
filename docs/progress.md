## Decision log

| Date | Decision | Rationale |
|---|---|---|
| 2026-09-21 | LF-only policy via committed `.gitattributes` (`* text=auto eol=lf`) | two-platform WSL/Windows development; committed attributes beat per-machine config |
| 2026-09-21 | remark-language-server hosts realtime diagnostics in phase 1; dedicated LSP is the end state | fastest path to editor diagnostics; validator core is transport-independent |
| 2026-09-21 | Relation directions fixed per type in the vocabulary; no per-relation direction config | deterministic cycle detection (MDL305); one definition of each type |
| 2026-09-21 | `apply_metadata_patch` is the only path from proposal to Front Matter | LLM output never writes authoritative metadata directly |
| 2026-09-22 | MDL305 reports once per strongly-connected component (anchored on the lexicographically smallest path) | naive simple-cycle enumeration is exponential; a 20-document sparse ring must not OOM the CI gate |
| 2026-09-22 | Baseline suppressions are fully silent (no info-level echo) | prevent "ignore fatigue"; baseline diff trail is recorded via `baseline verify` mismatches instead |
| 2026-09-22 | `baseline verify`/`update` anchor on the repository root (`git rev-parse --show-toplevel`) | a sub-directory CI step must never bypass the gate by scanning only its subtree |
| 2026-09-22 | `selfReference: forbidden` is enforced at the workspace layer and reported as MDL103 | the config switch existed in M0 but had no enforcement point |
| 2026-09-22 | Heading slugs are byte-for-byte github-slugger parity (derived interval table, combining marks kept) | evidence anchors are authored from GitHub's rendering; a Unicode-interval approximation misjudged legal anchors |
| 2026-09-23 | LSP sync contract declared explicitly (openClose/change/save) per LSP 3.17 | an absent `change` means None, so a strict client would never push didOpen/didChange |
| 2026-09-23 | Rename onto an already-claimed id is refused with an error | applying the edit would fabricate MDL301 in every touched file |
| 2026-09-23 | MDL104 quick fix offered only for scalar unknown fields | deleting a block-valued key line leaves orphaned children and corrupts the YAML |
| 2026-09-23 | MCP `apply_metadata_patch` applies to the buffer snapshot suggest_metadata captured, in memory only | unsaved buffers must be patchable; the disk write stays the caller's deliberate step |
| 2026-09-23 | Proposal values are YAML-quoted when they carry `: ` or indicator characters | an unquoted `reason: TODO: explain…` fails YAML parsing |
| 2026-09-23 | `publishOne` filters `validateWorkspace` output by `diag.path` before publishing | MDL305 is graph-level, so the pass's `paths` scope does not reach it and the whole array was published to one document, with ranges converted against that document's line table |
| 2026-09-23 | `apply_metadata_patch` gains an explicit opt-in disk write (default stays diff-only) | the spec's M4 acceptance text ("proposal 经显式接受写入 Front Matter") and the tool description ("never writes, writing is the caller's job") contradict each other; the user resolved the contradiction in favour of an opt-in capability so the accept loop can finish without a second tool. Default behaviour is unchanged: no flag, no write. See leftovers #7 |

## Review cadence

Cross-reviews run per major document wave with two independent reviewers on different models, followed by an orchestrator adjudication pass. **2026-09-21 completed round 1**, a document-level cross-review (2 independent reviewers + adjudication), whose reports live in `docs/reviews/2026-09-21-round1-*` — the only review reports currently on disk.

After it, seven code-level red-team reviews were dispatched, one per milestone half: M0 (3 Major + 7 Minor), M1-a (1 Blocker + 6 Major + 9 Minor), M1-b (1 Blocker + 5 Major), M2-a (1 Blocker + 2 Major), M2-b (1 Blocker + 5 Major), M3-a (0 Blocker + 5 Major), M3-b (0 Blocker + 5 Major + 6 Minor). **These seven reports exist only in the session record, not in the repository** — `docs/reviews/` holds round 1 alone, and `grep -rn "M3-b" docs/` matches only the matrix row above. The M3-b Minor set was therefore never schedulable from the repository alone; it is recorded in the leftovers table below instead. **M4 was not reviewed**: no dispatch record exists for it, so its Owner column reports self-fixes rather than an independent review.

Writing the seven missing reports into `docs/reviews/` is itself an open item (leftovers #14): without them, the project's history cannot be self-certified from the repository alone.
