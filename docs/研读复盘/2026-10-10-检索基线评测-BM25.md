# 【检索基线】BM25-only 文档级评测

## 评测目的

Issue #3 Phase 1 交付纯词法检索管道（章节切分 → CJK bigram + 标识符分词 → BM25）。本文记录该管道在**本仓库自身文档**上的可重复评测基线，作为 Phase 2 双路召回（BM25 + dense 向量 RRF 融合）与精排（Qwen3-Reranker）对比的锚点：没有词法基线，"+15 个百分点 Recall@10" 的验收门槛无从度量。

## 评测方法

- **脚本**：`node scripts/retrieval-eval.mjs`（支持 `--json` / `--verbose`），读取构建产物（`npm run build` 后运行），零网络、零模型。
- **语料口径**：`scanWorkspaceUniverse` 全工作区 Markdown（60 篇文档 / 402 个章节，含 `test/fixtures/`），与 `mdlineage retrieve search` 命令的扫描口径一致；章节经 `extractSections` 切分（Front Matter 剥离、8K token 截断、代码块字面保留）。
- **样本构造**（规则生成，不用模型）：
  1. 主层：`docs/**` Front Matter `relations` 中 `depends_on` / `refines` 且目标可解析到 docs 树内文档的关系对；查询文本 = 关系 `reason`（无 reason 用源文档标题），期望命中 = 目标文档；
  2. 补充层 A：其余关系类型（`implements` / `supersedes` / `contradicts` / `example_of` / `related_to`）；
  3. 补充层 B：topics 重叠文档对（查询 = 源文档标题）；
  4. 目标区间 40–60 对，按 `(source, target, query)` 去重后截断。
- **检索粒度**：文档级——章节命中按所属文档取最高分归并，排序按分数降序、路径字典序 tie-break（与词法分支确定性铁律一致）。
- **指标**：Recall@10（目标进入前 10 的样本占比）、MRR@10（前 10 内平均倒数排名，未进前 10 记 0）。

## 样本集现状

实得 **10 对**（4 对 relation:depends_on + 6 对 topics），低于 40–60 对目标。原因：`docs/**` 的 Front Matter 中真实关系仅 13 条（含本文新增的 1 条），其中能在 docs 树内解析到目标的有 4 条；使用手册与架构设计文档中的大量 `relations` 字样是**正文示例代码**，不参与解析。topics 重叠集中在 `reading-progress` 主题的 3 篇研读复盘文档（有序对 6 个）。脚本在样本不足时输出 `warning`，该短板已登记 progress.md leftover #32——基线数字可用但统计力度弱，Phase 2 对比结论需在样本扩充后复核。

## 评测结果（BM25-only）

| 指标 | 结果 |
|---|---|
| 样本对数 | 10 |
| 语料 | 60 文档 / 402 章节 |
| **Recall@10** | **100.0%**（10/10） |
| **MRR@10** | **0.240** |

逐档分布：rank 1 共零对；rank 2–3 共三对；rank 4–10 共七对；rank > 10 共零对。

## 逐档失败案例分析

> 本节"失败"指未进 rank 1（MRR 的主要损失来源），因为 Recall@10 无一失手。另注：本报告自身也在语料中（自指语料），本文数字为脚本在本报告最终落库版本上的实测输出；此后任何正文改动都会让个别名次轻微漂移，复跑以脚本输出为准。

**rank 1：0 对。** 没有任何查询把目标文档排在第一位，这是 MRR 仅 0.240 的直接原因。

**rank 2–3：三对（本文自指的 relation 对 + 两对 topics 互指，均为 rank 3）。** 本文自指对（查询逐字复述目标标题里的概念：跨模块、派生状态、联邦索引）属于词面强重叠的"易题"，却仍被回声邻居挤到第三；topics 互指对同理：同目录文档标题词高度同源（研读复盘、系统架构、跨模块），目标与邻居几乎同分。

**rank 4–10：七对（其余三对 relation + topics 中指向 README 方向的四对）。** 典型案例一：查询"研读复盘依赖系统架构设计中的双层索引模型与四阶段保鲜漏斗。"，目标 `docs/架构设计/系统架构.md` 排第 6；压过它的前五名依次是：本报告自身（正文引用了该查询原文，词法上成为最强回声）、源文档自身（**reason 的词面内容正是源文档正文的回声**——研读复盘正文通篇讨论"系统架构、双层索引、保鲜漏斗"）、docs/README.md（导航页密集罗列"系统架构"等词）、研读复盘/README.md、另一篇研读复盘——目标与第 5 名几乎同分。典型案例二：查询"研读复盘导航地图与阅读看板"（源 = 研读复盘/README.md 的标题），rank 1 恰是源文档自身，两篇复盘长文目标分别排第 5、6——短文档在 BM25 长度归一化（b=0.75）下占优。

这一档揭示了词法检索在本任务上的结构性弱点：**引用概念的文档（回声）与定义概念的文档（目标）在词面上不可区分**，中文 bigram 进一步放大高频双字词的支配力。这正是 Phase 2 dense 向量（语义上"定义文档"与概念距离更近）与 rerank 精排（交叉编码器直接比较 query-文档对）要解决的问题；另一个低成本的协议级改进候选——评测时把源文档从候选集中剔除（本评测中源文档频繁占据 rank 1–2）——涉及评测口径变更，留给协调者决策（leftover #32）。

## 结论与后续动作

1. Phase 1 词法管道的确定性契约（tie-break、逐字节稳定输出）在评测中成立：同一命令两次运行输出逐字节一致。
2. Recall@10 满分但 MRR 仅 0.240：目标总能进前 10，但词法模型几乎无法把"定义文档"排到"回声文档"（源文档、导航页、自引报告）之前——质量短板集中在排序头部，恰好落在 Phase 2 dense/rerank 的打击区。
3. 后续动作：扩充 `docs/**` Front Matter relations（leftover #32）；Phase 2 落地后按上表逐档回填并重算增量。
