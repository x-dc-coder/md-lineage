# README 门面与目录导航契约规范

状态：现行有效。本文档定义本仓库中各级导航页面（Landing Page）的设计定位、内容边界以及自动化硬性质量预算指标。根目录下的 `README.md` 是项目的第一门面；`docs/使用手册/` 下的手册则是详尽的权威参考手册。

## 适用范围

| 目标文件 | 角色定位 | 遵守契约 |
| --- | --- | --- |
| `README.md`（根目录） | 项目整体门面与快速索引 | 完整契约（条款 1–7） |
| 各子目录下的 `*/README.md` | 子目录导航大纲与索引 | 轻量契约（条款 1L、2、7） |
| `test/fixtures/**` | 测试用例文档与数据资产 | 自动豁免——作为普通文档处理 |

并非所有子目录都必须创建 `README.md`：仅当该目录需要提供全景地图与导读时才行创建，不强制平铺。

## 命名规范

人工手写的目录导航页面统一命名为 `README.md`——GitHub 网页端在浏览该目录时会自动就地渲染，符合导引页面的直觉。`INDEX.md` 保留给**机器自动化生成**的索引清单（如 `docs/架构设计/目录契约设计.md` 中设想的 `intent.catalog` 自动索引能力）。不引入第三种命名风格。

## 设计定位

导航页仅负责回答“当前目录承载了什么、下一步应当查阅哪里”，不做展开阐述。它是一张导航地图，而非详尽的操作手册。

## 语言要求

人工手写的导航页统一采用中文。本仓库面向开发者的核心手册（`docs/使用手册/**`）均采用中文，根目录 README 保持一致，避免维护双语引发事实漂移。若后续需要国际化入口，推荐新增轻量精简的 `README.en.md`（包含定位、安装及关键链接），而不全量复制双份文档。

## 不引入孤立事实原则

导航页中的每一处事实陈述，必须在 `docs/使用手册/**` 或 `docs/架构设计/**` 中已经存在详实支撑。导航页负责归纳和分发链接，严禁成为某些事实概念的唯一承载地。

## 结构与预算指标（根目录门面）

| 章节名称 | 承载内容 | 行数与体量预算 |
| --- | --- | --- |
| 标题与一句话定位 | 项目是什么，解决什么核心问题 | ≤ 3 行 |
| 快速开始 | 安装、初始化、校验以及单条简短输出示例 | ≤ 20 行 |
| 核心能力 | 4–6 条精炼的一句话功能点清单 | ≤ 10 行 |
| 常用命令 | 新手实际高频需要的命令速查表 | ≤ 12 行 |
| 文档 | 直达 `docs/使用手册/**` 的模块化链接导航 | ≤ 10 行 |
| 开发 | 克隆、构建、测试与自检命令 | ≤ 10 行 |
| 许可证 | 开源协议标注 | ≤ 2 行 |

子目录导航页不强求固定章节结构——通常映射其所索引的目录树，但需符合下述轻量预算。

## 机器硬性校验条款

根目录门面（`README.md`）：

1. 总长度不超过 100 行；
2. 恰好包含 1 个一级标题 `#`，且标题层级不深于 `##`；
3. 不超过 5 个围栏代码块，每个代码块不超过 12 行；
4. 不超过 2 张 Markdown 表格；
5. 每个 `##` 章节内容不超过 15 个非空行，每个段落不超过 3 行；
6. 前 15 行内必须出现代码块（保障快速开始命令首屏即见）；
7. 所有超链接目标必须为相对路径——严禁外链与徽标图片。

子目录导航页（`*/README.md`）：

1L. 总长度不超过 120 行；
2. 恰好包含 1 个一级标题 `#`，且标题层级不深于 `##`；
7. 所有超链接目标必须为相对路径。

由人工审查而非脚本硬性判定的条款：不引入孤立事实原则、导航页仅做指引的定位，以及读者首屏即可看懂并运行工具的可读性体验。

## 执行与自动化门禁

脚本 `scripts/check-readme.mjs` 在 CI 流水线中自动遍历仓库（跳过 `.git`、`node_modules` 与 `dist`），对根目录与各级 README 应用上述规则，并在 GitHub Actions 的 `gates` 阶段中进行刚性拦截。任何调整预算限制或扩展监控目标的操作，必须在同一提交中同步修改本文档与校验脚本。
