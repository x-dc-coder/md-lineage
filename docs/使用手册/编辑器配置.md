# 编辑器与 IDE 集成配置指南

MDLineage 提供专用的语言服务器（LSP）与面向 AI Agent 的 MCP 服务，支持在 VS Code、Neovim、Cursor 等编辑器中实时进行 Markdown 元数据补全、错误波浪线提示、跨文档定义跳转与快速修复。

相关文档：[`使用指南.md`](./使用指南.md)（快速入门）、[`配置指南.md`](./配置指南.md)（配置文件参考）、[`诊断码速查.md`](./诊断码速查.md)（诊断码说明）。

---

## 1. 语言服务（LSP）能力清单

通过 `mdlineage server --stdio` 启动专用语言服务器，提供以下 IDE 原生体验：

- **智能自动补全（Completion）**：
  - 键入关系 `type:` 时自动提示 7 种标准关系枚举；
  - 键入关系 `target:` 时自动模糊匹配并补全全工作区所有已注册的文档 ID；
  - 键入 `evidence:` 时自动枚举并补全目标文档内所有合法的标题锚点（`#section-slug`）；
  - 补全 `kind`、`status`、`authority` 词汇表枚举值。
- **定义跳转与引用查找（Go to Definition / Find References）**：
  - 光标停留在 `target: docs.authentication-model` 上按下 `F12`，秒级跳转至目标文档的声明位置；
  - 在关系目标或相对链接上按下 `Shift+F12`，反查全仓所有引用该文档的来源列表。
- **文档大纲与全局符号搜索（Workspace Symbol）**：
  - 按下 `Ctrl+T` 或 `Ctrl+P` 输入 `#`，直接按文档 ID、别名（aliases）或标题大纲进行全仓模糊检索。
- **快速修复（CodeAction）**：
  - 对 `MDL102`（缺少必填字段）提供“插入必填字段骨架”快捷修复；
  - 对 `MDL202`（重复关系）提供一键删除冗余项；
  - 对 `MDL104`（未知字段）提供一键清理。
- **低开销防抖与容灾**：
  - 200ms 编辑防抖；单文件更新后仅定向重算受影响的下游依赖，不产生编辑器卡顿；单文档超过 2MB 自动降级为安全提示。

## 2. 常见编辑器接线配置

### 2.1 VS Code 配置

使用 VS Code 通用 LSP 扩展客户端或项目 `.vscode/settings.json` 进行配置：

```json
{
  "mdlineage.lsp.command": "node",
  "mdlineage.lsp.args": [
    "/absolute/path/to/md-lineage/packages/language-server/dist/server-entry.js",
    "--stdio"
  ]
}
```

或者通过通用 stdio LSP 客户端插件（如 *Generic LSP Client*）：
- **Language**: `markdown`
- **Command**: `node`
- **Args**: `["/path/to/packages/language-server/dist/server-entry.js", "--stdio"]`

### 2.2 Neovim 配置（原生 LSP）

在 `init.lua` 中配置 `vim.lsp.start`：

```lua
local lspconfig = require('lspconfig')

vim.api.nvim_create_autocmd('FileType', {
  pattern = 'markdown',
  callback = function(ev)
    vim.lsp.start({
      name = 'mdlineage',
      cmd = {
        'node',
        vim.fn.expand('~/projects/md-lineage/packages/language-server/dist/server-entry.js'),
        '--stdio'
      },
      root_dir = vim.fs.root(ev.buf, { 'mdlineage.config.yaml', '.git' }),
    })
  end,
})
```

## 3. 面向 AI Agent 的 MCP 服务集成

MDLineage 的 MCP 服务通过 `mdlineage mcp --stdio --root <dir>` 运行，为大模型 Agent 暴露 7 个专注于知识库结构治理的结构化工具：

### 3.1 客户端配置（Claude Desktop / Claude Code / Grok / Cursor）

在客户端的 MCP 配置文件中添加：

```json
{
  "mcpServers": {
    "mdlineage": {
      "command": "node",
      "args": [
        "/absolute/path/to/md-lineage/packages/cli/dist/main.js",
        "mcp",
        "--stdio",
        "--root",
        "/path/to/your/markdown/workspace"
      ]
    }
  }
}
```

### 3.2 暴露的核心工具列表

| 工具名称 | 功能描述 | 核心参数与行为 |
|---|---|---|
| `validate_document` | 单文档内存校验 | 支持传入 `content` 直接校验未保存的临时文本 |
| `validate_repository` | 全工作区拓扑校验 | 校验 ID 重复、悬空目标与成环，自动应用基线抑制 |
| `get_schema` | 获取元数据 Schema | 返回标准 JSON Schema 供模型生成 Front Matter 前参考 |
| `list_document_ids` | 枚举全仓已纳管 ID | 支持按 `kind` 或关键词过滤 |
| `resolve_relation_target`| 反解目标 ID | 查询指定 ID 的物理路径、标题大纲与反向引用者 |
| `suggest_metadata` | 确定性只读元数据提案 | 分析单篇文档并生成修复提案，返回 `proposal_id` |
| `apply_metadata_patch` | 应用元数据修改 | 默认只返回预览 Diff，显式传 `write: true` 时经过四重安全守卫后原子落盘 |

### 3.3 写盘安全守卫机制
在 Agent 调用 `apply_metadata_patch(write: true)` 时，服务实行四重前置防护：
1. **防路径逃逸**：目标物理路径经过 `realpath` 展开，必须严格落在 `--root` 工作区内部；
2. **防覆盖冲突**：磁盘文件哈希必须与提案生成时的哈希完全一致，防止覆盖他人最新的并发编辑；
3. **文件存在性与权限**：文件在磁盘上必须真实存在且具备可写权限；
4. **原子落盘**：写入经临时文件原子 `rename` 完成，杜绝写入中断导致的数据损坏。
