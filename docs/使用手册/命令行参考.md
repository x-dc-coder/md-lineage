# CLI 命令行参考

**`mdlineage`** 是 MDLineage 的命令行入口，提供 Markdown 知识库的元数据校验、跨文件关系图谱构建、链接与锚点完整性检查、行尾卫生治理以及目录拓扑重构功能。

相关文档：[`使用指南.md`](./使用指南.md)（快速入门与五大包概览）、[`配置指南.md`](./配置指南.md)（配置文件参考）、[`全场景通用知识库目录规范.md`](./全场景通用知识库目录规范.md)（目录规范）。

## 1. 安装与构建

MDLineage 包含五个 npm 包：`@mdlineage/validator`（校验与索引核心）、`@mdlineage/remark-lint-mdlineage`、`@mdlineage/cli`、`@mdlineage/language-server` 和 `@mdlineage/mcp-server`。运行环境要求 Node.js `>= 20`。

在仓库根目录下构建：

```bash
npm ci
npm run build
```

`npm run build` 执行 `tsc -b && node scripts/ensure-bin-exec.mjs`。构建完成后，直接调用 CLI：

```bash
node packages/cli/dist/main.js --version
```

日常开发常用脚本：

| 脚本命令 | 行为说明 |
|---|---|
| `npm test` | 执行全量构建并运行全部 666 个单元与集成测试 |
| `npm run lint:md` | 运行 remark 严格门禁校验 `docs/` 和 `README.md`（`--frail`） |
| `npm run check:md` | 运行 `mdlineage check .` |
| `npm run check:md:changed` | 运行 `mdlineage check --changed` 仅检查 Git 变动文档 |
| `npm run clean` | 清理 TypeScript 构建缓存 |

## 2. 通用约定与选项

### 2.1 退出码契约

所有子命令遵循统一的退出码规范：

| 退出码 | 含义 |
|---|---|
| `0` | 无 error 级诊断（试运行成功、无错误等） |
| `1` | 存在至少一个 error 级诊断、文件不可读、配置损坏（`--frail` 模式下任何级别诊断均退出 1） |
| `2` | 命令行用法错误（未知选项、未知命令、非法的 `--format` 值等） |

### 2.2 工作区根目录锚定

不同命令根据其设计职责锚定不同的工作区根目录：

| 命令分类 | 根目录锚定 | 说明 |
|---|---|---|
| `check`、`fix`、`move`、`organize` | 当前工作目录（CWD） | 路径基于 CWD 解析，拒绝操作 CWD 之外的逃逸路径 |
| `baseline`、`init` | Git 仓库根目录 | 若不在 Git 仓库内则回退为 CWD（属于仓库级契约） |
| 配置文件查找 | 从 CWD 向上回溯查找 | 支持在任意深层子目录下执行并自动发现根配置 |

### 2.3 全局通用选项

- `--format <text|json|sarif>`：输出格式（默认为 text，详见下文）。
- `--config <path>`：显式指定 `mdlineage.config.yaml` 路径。
- `--frail`：严苛模式，任何 warning 或 hint 均导致命令以退出码 1 失败。
- `--exclude <pattern>`：追加排除的路径 glob（可重复指定）。
- `--no-incremental`：关闭跨文件工作区分析，退化为纯单文档独立语法校验。
- `--no-baseline`：忽略 `.mdlineage-baseline.json` 基线，暴露所有已接受的历史债务。

## 3. 子命令详解

### 3.1 check（权威校验）

```bash
mdlineage check [paths...]        # 校验指定路径或当前目录（默认 CWD）
mdlineage check --changed         # 仅校验 Git 变动的文件
mdlineage check docs --frail      # 严苛校验 docs 目录
```

`check` 命令执行权威的单文档与跨文档全量校验。先执行各文档的 Front Matter、Schema 与行尾扫描，再由工作区索引层补充执行：
- `MDL301`：跨文件 ID 重复检测；
- `MDL302`：关系依赖目标 ID 存在性解析；
- `MDL305`：禁止成环关系类型的强连通分量检测；
- `MDL306`：活跃文档引用已废弃目标的拦截；
- `MDL401` / `MDL402` / `MDL403`：相对链接、标题锚点片段与宿主路径校验；
- `MDL501`–`MDL505`：目录规范与意图契约校验。

#### 输出格式：
- **`text`（默认）**：`path:line:col CODE severity message`，控制台单行输出加统计汇总。
- **`json`**：输出包含 `reports`、`unreadable`、`configDiagnostics`、`summary` 的结构化 JSON 树。
- **`sarif`**：输出标准 SARIF 2.1.0 格式报告，无缝集成 GitHub Code Scanning。

### 3.2 baseline（基线管理）

```bash
mdlineage baseline update         # 将当前全仓诊断记录为已接受的债务
mdlineage baseline show           # 按诊断码统计已提交基线中的债务条目
mdlineage baseline verify         # CI 严格门禁：校验当前诊断与基线是否完全一致
```

基线存储于仓库根目录下的 `.mdlineage-baseline.json`，是提交进版本控制的团队契约。`verify` 在 CI 流水线中运行：既不容忍引入新违规，也不允许残留已经修复的历史条目。

### 3.3 move（单文档安全移动与链接自愈）

```bash
mdlineage move <src> <dst>           # 试运行（默认）：打印规划与受影响引用，零写盘
mdlineage move <src> <dst> --write   # 真正执行移动与全仓链接自愈
```

- **入边自动自愈**：全仓所有引用 `src` 的文档，相对链接根据新深度自动重算，保留原始 `#anchor` 锚点；
- **出边自动重算**：被移动文档内部指向外部文件与图片的相对路径，按新目录深度重新计算；
- **Git 历史保护**：优先使用 `git mv` 保持历史记录完整；
- **时钟刷新**：若包含 Front Matter，自动将 `updated_at` 刷新为当天日期。

### 3.4 organize（目录意图批量治理与全局重组）

```bash
mdlineage organize --inventory       # 盘点：统计全仓文档类别(kind)分布与未纳管孤儿文档
mdlineage organize --report          # 报告：评估目录 intent 规范合规率与例外统计
mdlineage organize --plan            # 规划：基于 layout.intent 检测错位文档，输出批量迁移建议
mdlineage organize --apply           # 执行：批量应用重组计划，迭代自愈全仓链接
```

- `--scope <glob>`：限制扫描与规划的子树范围；
- 批量执行时采用动态快照迭代算法，避免同一引用方被多次并发写入时覆盖丢失。

### 3.5 fix（安全自动修复）

```bash
mdlineage fix [paths...]             # 试运行，输出修复 diff 计划
mdlineage fix [paths...] --write     # 真正执行落盘修复
```

自动修复仅执行无歧义的机械性修正，决不擅自更改业务内容：
- **MDL102**：补全缺失的必填字段骨架；
- **MDL202**：删除同文档内逐字节重复的关系声明；
- **MDL103**：规范化词汇表中唯一的大小写不敏感枚举值；
- **MDL601/MDL602**：统一全文档行尾符为配置策略（LF/CRLF）。

### 3.6 init（项目脚手架初始化）

```bash
mdlineage init                       # 试运行，打印生成清单
mdlineage init --write               # 生成 mdlineage.config.yaml、.gitattributes、schemas/
```

### 3.7 suggest（只读元数据提案）

```bash
mdlineage suggest <file>             # 针对单个文件输出确定性元数据提案 JSON
```

### 3.8 config validate（配置校验）

```bash
mdlineage config validate [--format text|json]
```

快速校验当前 `mdlineage.config.yaml` 是否符合配置 Schema，退出码 0 表示配置合法。

### 3.9 index rebuild（内存索引重构）

```bash
mdlineage index rebuild [--format text|json]
```

在内存中构建完整的 `WorkspaceIndex`，输出纳入文档数、注册 ID 数、关系引用数与标题锚点总数，验证全局图谱连通性。

### 3.10 server 与 mcp（LSP 与 MCP 服务）

```bash
mdlineage server --stdio             # 启动专用语言服务器（供 VS Code / Neovim 接入）
mdlineage mcp --stdio --root <dir>   # 启动面向 AI Agent 的 MCP 服务
```
