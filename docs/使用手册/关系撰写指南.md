# 关系撰写指南

本指南面向 Markdown 仓库作者与维护者，阐述 Front Matter `relations` 字段的设计语义、类型选型、寻址拼写决策树、`evidence` 锚点定位规则以及跨仓联邦注意事项。

相关文档：[元数据规范.md](../架构设计/元数据规范.md)（规范定义）、[配置指南.md](./配置指南.md)（配置与联邦挂载）、[使用指南.md](./使用指南.md)（CLI 与日常工作流）、[诊断码速查.md](./诊断码速查.md)（排错速查）。

---

## 1. 为什么与边界

在 MDLineage 中，`relations` 表示文档之间**已确认的血缘关系**：

- **血缘与正文链接拓扑正交**：正文中的普通 Markdown 链接表示行文阅读导航；`relations` 表示语义结构层面的硬性约束、演进依赖与影响链路（元数据规范核心规则 5）。
- **反向边由索引派生，禁止手写**：例如 `A depends_on B` 声明后，反向的“被依赖”集合由工作区索引自动聚合派生。作者严禁在 `B` 中反向手写 `depended_by` 等伪字段（核心规则 4）。

## 2. 关系类型（type）选择表

MDLineage 内置 7 种标准关系类型。下表列出系统内置默认开关（可在 `mdlineage.config.yaml` 的 `relations:` 下自定义覆盖，参见 [配置指南.md](./配置指南.md) §2.5）：

| type | impact | reason 必填 | selfReference | cycles | 适用场景 | 常见误用 |
|---|---|---|---|---|---|---|
| `depends_on` | ✓ | ✓ | forbidden | — | 强依赖：目标文档定义的规则/接口/前置假设变动会破坏本文档 | 将普通背景阅读文档写成强依赖 |
| `implements` | ✓ | ✓ | — | — | 实现落地：本文档是目标设计方案或架构决策的具体实现 | 用于表述两个同级设计文档的关系 |
| `refines` | ✓ | ✓ | — | — | 细化收窄：细化、补充或特化目标文档中的抽象规则 | 替代或推翻目标文档规则 |
| `supersedes` | ✓ | ✓ | — | forbidden | 替代废止：替代目标文档成为现行指引，目标应随后转入 deprecated | 仅仅修改部分章节时替代整篇文档 |
| `contradicts` | ✗ (人工复审) | ✓ | — | — | 主张冲突：标记当前文档与目标文档存在分歧，等待治理 | 长期悬挂冲突而不推进对齐 |
| `example_of` | ✗ | ✗ | — | — | 样例承载：作为目标概念、架构模式或接口的具体示例 | 承载业务主流程的文档作为示例 |
| `related_to` | ✗ | ✗ | — | — | 广义关联：探索期关联、泛主题指引或上下文关联 | 替代本应明确权责的 `depends_on` |

> **提示**：对于 `impact`（影响传播）类关系，`reason` 字段为必填。若遗漏该字段会触发 `MDL102`；若字段值为空字符串或纯空白字符，则在工作区校验时触发 `MDL304`。

## 3. target 四种拼写决策树

编写 `relations[].target` 时，请按下列决策树选择拼写形式（详见 [配置指南.md](./配置指南.md) §2.10）：

```text
目标文档位于何处？
├─ 本仓库内部 ──> 裸 id (例如: docs.configuration) [默认，最稳健]
└─ 跨仓库引用
   ├─ 主仓引用指定联邦成员 ──> @<scope>//<id> (例如: @member-a//docs.api)
   ├─ 联邦成员引用主仓 ──────> @home//<id> (例如: @home//docs.shared)
   └─ 探索期未知所属成员 ────> @*//<id> (慎用，若多仓命中将触发 MDL307 歧义错误)
```

### 详细说明

1. **裸 id（默认）**：`target: docs.configuration`。仅在本仓库范围内解析。若 target 拼写不存在，将报告 `MDL302`。
2. **`@<scope>//<id>`**：跨仓稳定依赖推荐形式。显式指定目标成员作用域。当成员未挂载时，若配置 `missing: warn` 则报告 `MDL308` 提示，若为 `missing: error` 则直接拒绝并报 `MDL902`。
3. **`@home//<id>`**：成员仓库反向引用宿主主仓的标准形式。注意：当成员仓库在**独立本地 CI**（未挂载宿主）中运行时，`@home` 会诚实降级报告 `MDL302`（因为 `@home` 是保留域，成员不能自声明为 home）。这是预期行为，合流到宿主工作区时即可正常闭环。
4. **`@*//<id>`**：通配成员查询。仅用于重构或跨仓探索期。一旦有两个或以上成员声明了相同 `id`，将立即报告 `MDL307`（error 级别）阻止构建。

## 4. 文档 id 命名约定

Front Matter 的 `id` 必须严格遵循正则模式 `^[a-z0-9]+(?:[.-][a-z0-9]+)*$`：

- **惯例前缀**：推荐采用 `docs.<topic>` 或 `<domain>.<name>`（例如本仓库中的 `docs.configuration`、`docs.user-handbook`）。
- **中文与特殊路径**：中文文档文件名若直接转 slug 会塌缩为 `docs`，因此必须显式指定英文字母与数字组合的 ASCII `id`。
- **不可变性**：文档文件改名或在目录树中移动时，`id` 保持不变（元数据规范核心规则 1），所有指向该文档的 relation 边均不会中断。
- **查重验证**：在撰写新 relation 前，可借助 MCP 工具 `list_document_ids` / `resolve_relation_target` 或运行 `mdlineage index rebuild` 预先核实目标标识。

## 5. reason 与 evidence 撰写规范

### 5.1 reason 写法

对于强影响关系（如 `depends_on`、`implements`、`supersedes` 等），`reason` 必须是一句简明扼要的事实说明，阐明为什么该关系成立。例如：

```yaml
relations:
  - type: depends_on
    target: docs.auth-spec
    reason: "依赖 Token 签发与刷新协议规范"
```

### 5.2 evidence 锚点与所有权规则

`evidence` 必须为以 `#` 开头的标题定位锚点（例如 `evidence: "#cache-policy"`）：

- **目标文档定位**：`evidence` 始终解析到 relation 的 **target 文档**（GFM 标题 slug 化，支持中英文标题与 emoji）。
- **跨文档与联邦归属（MDL402）**：当 target 指向本仓其他文档、或通过 `@scope//id` 指向联邦成员时，目标文档若缺失对应标题，由工作区校验层报告 `MDL402`。
- **自指文档归属（MDL201）**：当 relation 的 target 指向当前文档自身（裸 own id）时，该锚点在本文档正文中查找。若本文档缺失该标题，由单文档语义层报告 `MDL201`。
- **双报消除保证**：校验核心对自指裸 id 关系进行了守卫过滤（每个锚点在全仓校验中恰好报告一次，消除了 `MDL201` 与 `MDL402` 的重复报告）。若通过信封自指（如在主仓中写 `@home//own-id`），守卫将跳过单文档层并交由 `MDL402` 统一检验。

## 6. 联邦特有注意事项

在多仓联邦协作场景下，请牢记以下约束：

1. **成员只读契约（`trust: readonly`）**：所有跨仓引用的成员仓库均为只读挂载。CLI 的 `fix` 或 MCP 的 `apply_metadata_patch` 会自动阻止对 `@scope//` 路径的写入操作。
2. **退出码主权**：成员仓库产生的错误在主仓校验时会被封顶降级为 `warning`，因此不会直接导致主仓的 CI 退出码失败（除非开启 `--frail`）。
3. **成员缺失延迟诊断**：若配置了 `missing: warn`，当某个成员未挂载时，对其内部的引用将产生 `MDL308` 提示，而不是直接报严重阻断错误。

常见联邦排查码：
- `MDL302`：未知的 scope 前缀，或者误在裸 id 模式下跨仓寻找；
- `MDL307`：通配符 `@*//id` 匹配到了多个成员；
- `MDL308`：目标成员未在本地挂载（配置了 `missing: warn`）。

## 7. 工作流自检与收尾

在修改或新增关系定义后，建议执行下列命令进行本地验证：

```bash
# 1. 运行本地仓库全量校验
./node_modules/.bin/mdlineage check .

# 2. 验证基线是否存在未登记漂移
./node_modules/.bin/mdlineage baseline verify
```

若在 AI 辅助开发环境下，可直接调用 MCP 工具 `validate_repository`，并按需传入过滤参数：

- `severityThreshold: "error"`：只关注阻断级错误；
- `external: "exclude"`：暂时过滤掉联邦成员的告警，专注排查本仓关系。
