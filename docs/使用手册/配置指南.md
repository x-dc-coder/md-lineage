# 配置文件参考（mdlineage.config.yaml）

MDLineage 遵循清晰的两层职责边界：
1. **各文档自身的 Front Matter（`mdlineage:` 块）**：声明文档自身的稳定身份（`id`）、属性分类（`kind`、`status`、`authority`）与已确认的关系血缘（`relations`）。
2. **仓库根目录的 `mdlineage.config.yaml`**：声明不可执行的**规则与治理范围**（哪些文件纳入扫描、合法词汇表、目录意图契约、每种关系的约束以及诊断码的严重级别覆盖）。

配置文件**永远不是可执行代码**，不包含业务文档内容。即使删掉所有配置文件，语料库本身仍然成立。

相关文档：[`使用指南.md`](./使用指南.md)（快速上手与入门）、[`诊断码速查.md`](./诊断码速查.md)（错误码排查）、[`全场景通用知识库目录规范.md`](./全场景通用知识库目录规范.md)（目录规范）。

## 1. 顶层配置键总表

在 `mdlineage.config.yaml` 中，只有 `configVersion` 必填（必须为 `1`），其余字段全部可选：

| 顶层配置键 | 类型 | 默认值 | 作用与控制范围 | 关联诊断码 |
|---|---|---|---|---|
| `configVersion` | number | — (必填，须为 `1`) | 配置文件模式版本 | MDL900（其他值报错） |
| `files` | object | 见下文 | 工作区扫描的文件发现范围与符号链接行为 | — |
| `manifestFile` | string | 未设置 | 外部旁路元数据清单 YAML 文件相对路径（方案四） | MDL900（文件缺失或语法错） |
| `manifest` | object | 未设置 | 内联旁路元数据清单（包含 `documents` 映射） | MDL900 |
| `links` | object | 见下文 | Linux 宿主路径与 `~`、`$HOME` 展开策略 | MDL403 |
| `metadata` | object | 见下文 | Front Matter 提取与缺失检测行为 | MDL003, MDL104 |
| `vocabulary` | object | 见下文 | 合法的 `kind`、`status`、`authority` 词汇表 | MDL103 |
| `relations` | object | 见下文 | 每种关系类型的严格度开关（成环、自引用、必填理由） | MDL103, MDL304, MDL305 |
| `lifecycle` | object | 见下文 | 废弃依赖拦截与文档时效时钟策略 | MDL306, MDL801 |
| `diagnostics` | object | 码表默认 | 覆盖特定诊断码的严重级别（`error` / `warning` / `information` / `hint`） | 任意诊断码 |
| `eolPolicy` | string | `lf` | 换行符策略（`lf` / `crlf` / `cr`） | MDL601, MDL602 |
| `schemaFile` | string | 未设置 | 指向自定义的元数据扩展 JSON Schema | MDL102, MDL104, MDL900 |
| `extends` | string[] | 未设置 | 继承的组织或上游预设配置列表 | MDL900 |
| `layout` | array | 未设置 | 目录结构约定与目录意图契约（P4） | MDL501, MDL502, MDL504 |
| `layoutExceptions` | array | 未设置 | 带有截止日期的目录意图豁免例外清单 | MDL503 |
| `policies` | object | 未设置 | 预留的仓库策略 DSL（当前未激活） | — |

未知顶层键会被模式校验直接拦截并报 `MDL900`（如手误写成 `diagnostic:` 不会被静默忽略）。

## 2. 核心模块配置详解

### 2.1 `files`（文件发现与符号链接）

```yaml
files:
  include: ['**/*.md']
  exclude: ['node_modules/**', 'dist/**', 'vendor/**']
  followSymlinks: true     # 是否跟随符号链接遍历目录（默认 true）
  symlinkMaxDepth: 10      # 符号链接遍历最大嵌套深度（默认 10）
```

- 内置排除目录（`node_modules/**`、`dist/**`、`vendor/**`）始终自动前置生效；
- `followSymlinks: true` 时，底层采用逻辑路径投影模型，配合 `realpath` 集合进行 $O(1)$ 自环拦截，安全穿透深层参考文档。

### 2.2 `links`（Linux 宿主路径与可移植性）

```yaml
links:
  expandTilde: true        # 是否展开 ~ 与 $HOME（默认 true）
  allowHostPaths: warning  # 策略：always | warning | forbidden
```

- **`warning`（默认）**：宿主机物理文件不存在报 `MDL403 warning`；存在但位于工作区外部报不可移植提示；存在且位于工作区内部则给出相对路径建议。
- **`always`**：只要宿主机文件存在即完全静默放行（0 诊断）。
- **`forbidden`**：严格拒绝所有宿主路径并报 `MDL403 error`（适合沙箱 CI 环境）。

### 2.3 `metadata`（元数据提取与校验）

```yaml
metadata:
  key: mdlineage            # Front Matter 中元数据顶级键名，默认 mdlineage
  required: true            # 开启时无元数据报 MDL003；false 全仓抑制
```

### 2.4 `vocabulary`（合法词汇表）

```yaml
vocabulary:
  kinds: [policy, guide, architecture, reference, spec, report, plan, vision]
  statuses: [draft, active, deprecated, archived]
  authorities: [canonical, supporting]
```

超出词汇表的取值会在对应文档中报告 `MDL103` 错误。

### 2.5 `relations`（关系类型严格度控制）

七种标准关系类型（`depends_on`、`implements`、`refines`、`supersedes`、`contradicts`、`example_of`、`related_to`）的内置开关：

| 关系类型 | `impact` | `reasonRequired` | `selfReference` | `cycles` | `severity` |
|---|---|---|---|---|---|
| `depends_on` | `true` | `true` | `forbidden` | — | — |
| `implements` | `true` | `true` | — | — | — |
| `refines` | `true` | `true` | — | — | — |
| `supersedes` | `true` | `true` | — | `forbidden` | — |
| `contradicts` | — | `true` | — | — | `warning` |
| `example_of` | `false` | — | — | — | — |
| `related_to` | `false` | — | — | — | — |

- `impact: true`：驱动变更影响面分析；
- `reasonRequired: true`：当 `reason` 为空时触发 `MDL304`；
- `selfReference: forbidden`：当指向自身文档 ID 时触发 `MDL103`；
- `cycles: forbidden`：成环时触发 `MDL305`（按强连通分量报告，每个环只报一次）。

### 2.6 `lifecycle`（生命周期时钟与废弃拦截）

```yaml
lifecycle:
  staleAfterDays: 180           # 超过 N 天未更新报 MDL801（0 为关闭）
  staleStatuses: [active]       # 仅监控 active 状态文档的时效
  deprecatedStatuses: [deprecated]
  blockingRelations: [depends_on, implements, refines] # 引用已废弃目标触发 MDL306
  exempt:
    - 'docs/历史归档/**'        # 豁免时效检查的路径 glob
```

时钟检查优先级：文档手写的 `updated_at` → 手写的 `created_at` → Git 提交历史回退时钟。

### 2.7 `layout` 与 `layoutExceptions`（目录意图契约）

```yaml
layout:
  - match: '**/*.md'
    require:
      frontmatter: optional
  - match: 'docs/**'
    require:
      frontmatter: required
  - match: 'docs/使用手册/**'
    intent:
      description: '面向终端开发者的现行中文使用与配置手册'
      kinds: [guide, reference]
      forbidStatus: [draft]
      maxDepth: 2

layoutExceptions:
  - path: 'docs/使用手册/legacy.md'
    reason: '待下个里程碑迁移至历史归档'
    expires: '2026-12-31'      # 到期自动失效并触发 MDL503 错误
```

- `intent.kinds`：约束目录内允许的文档类型，违背报 `MDL502`；
- `intent.naming` 与 `intent.maxDepth`：约束文件名正则与嵌套深度，超限报 `MDL504`；
- 未受任何目录意图纳管的孤儿文件报 `MDL505`。

### 2.8 方案四：旁路清单（`manifestFile` 与 `manifest`）

针对外部软链接（如 Agent 技能农场）或需保持正文 100% 字节不变的只读文档：

```yaml
manifestFile: mdlineage.manifest.yaml  # 相对当前配置目录解析
```

```yaml
# mdlineage.manifest.yaml 结构
version: 1
documents:
  skills/paper-reader/SKILL.md:
    id: skill.paper-reader
    kind: reference
    status: active
    relations:
      - type: depends_on
        target: skill.word-extractor
        reason: docx 高保真提取
```

清单内登记的文档自动豁免 `MDL003`，并在内存中挂载为一等公民图谱资产，享受全部依赖校验与查询能力。

### 2.9 `diagnostics`（严重级别覆盖）

```yaml
diagnostics:
  MDL304: error          # 将空白理由警告提升为 error 阻断
  MDL403: hint           # 将宿主路径警告降级为 hint 提示
```

可在不修改任何文档的情况下，通过配置调整 CI 检查的通过阈值。
