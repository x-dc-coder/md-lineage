# MDLineage 交叉审查报告（glm-5.3）

日期：2026-09-21。范围：全部 9 个文档。核查方法：(a) `git log`/blob 核对文档引用的提交与现场证据；(b) 本地 git 沙箱实验复现 `renormalize`/`checkout-index -f -a`/`status`/`diff`/`add` 在 CRLF 场景下的行为；(c) npm registry 与 GitHub 源码核验 remark 生态事实（remark-language-server 3.0.0、vscode-remark 3.3.1、unified-language-server、unified-args、yaml@2、Ajv、remark-frontmatter）；(d) mermaid CLI（mmdc 11.17.0）编译 architecture.md 的图；所有外部链接逐一 HTTP 检查。未修改任何文件。

## Blocker

**B1. docs/frontmatter-spec.md：示例使用词表外的 `refined_by`**
- 示例第二条关系 `refined_by` 不在七个词的词表中，违反本文件 Rules 第 3 条「使用允许的类型」——规范自带示例无法通过自身校验器。
- 建议：在目标文档中声明 `refines`，确保示例逐字段合法。

**B2. docs/remark-language-server-solution.md §6.1/§6.3：「编辑器启动仓库内版本」与 vscode-remark 真实行为矛盾**
- vscode-remark 3.3.1 将 remark-language-server 用 esbuild 打包进扩展（`dependencies` 为空，无 server 路径设置项），VS Code 下 server 版本随扩展走，「仓库内锁版本」只对 stdio 客户端（Neovim/Emacs）与 `.remarkrc.mjs` 加载的插件成立。
- 建议：区分两条通道；或为 VS Code 提供自带 client 的自定义扩展方案。

**B3. docs/line-ending-management.md §3 vs §4.3/§5：CI 门禁威胁模型与自身机制矛盾；`--changed` 检测基准未指明**
- 实验证实：`* text=auto eol=lf` 生效时，工作区 CRLF 修改的 `git diff --name-only` 为空（仅警告），`git add` 后暂存 blob 即 LF——「CRLF 潜入提交」在属性覆盖下基本不可能发生；朴素实现（基于 diff/暂存内容）的 `--changed` 会静默漏检 CRLF 修改。
- 建议：CI 门禁重定义为「校验 `.gitattributes` 存在且提交 blob 无 CRLF」的纵深防御；`--changed` 基于工作区字节扫描或 `git status --porcelain`。

## 总体结论
